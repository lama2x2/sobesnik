# CLAUDE.md

Правила работы с репозиторием Sobesnik для Claude Code.

## Проект

Sobesnik — self-hosted тренажёр технических собеседований на стороне кандидата.
Вакансия → вопросы под стек и уровень → ответ текстом или голосом → оценка языковой моделью
по рубрике → прогресс и повторение слабых тем. Бесплатный, разворачивается одной командой,
может работать полностью локально (распознавание речи и LLM на своём железе).

Стек: Python 3.12, FastAPI, async SQLAlchemy 2.0 + Alembic, PostgreSQL, Redis, S3-совместимое
хранилище, Aiogram 3, faster-whisper, Ollama, Docker Compose.

## LLM

- **По умолчанию всё работает и тестируется на Ollama.** Код, промпты и тесты не должны требовать
  облачного ключа.
- Опционально подключается OpenAI-совместимый API: если в env задан ключ и base URL — используется он.
  Переключение только через env, без правок кода.
- На macOS Ollama запускается **нативно на хосте** (в Docker на Маке нет доступа к GPU/Metal),
  контейнеры ходят в неё по `http://host.docker.internal:11434`. На Linux-сервере с GPU Ollama
  поднимается сервисом в compose (отдельный профиль).
- Данные для проверки качества — только открытые: публичные банки вопросов и датасеты с эталонными
  ответами. Живых экспертов-оценщиков нет.

## Структура

```
apps/api        HTTP API (FastAPI)
apps/bot        Telegram-бот
apps/web        веб-кабинет
packages/core   предметная область: вопросы, рубрики, оценки, прогресс
packages/llm    слой провайдеров LLM: единый интерфейс, переключение через env
packages/asr    распознавание речи
deploy          compose-профили и примеры env
research        эксперименты по качеству оценки
docs            архитектура, ADR, спецификации (docs/specs)
```

Зависимости проекта не импортируют друг друга по кругу: `apps/*` зависят от `packages/*`,
`packages/core` не зависит ни от чего внутри репо.

## Git

- **push и force-push — только с явного разрешения автора в чате, каждый раз заново.**
  Разрешение на один push не распространяется на следующие.
- Коммиты Claude делает сам по ходу работы — логическими шагами, после каждой завершённой части.
- Сообщения коммитов на русском: первая строка — что сделано, в повелительном наклонении
  («Добавить генератор вопросов»), дальше при необходимости — зачем.
- В конце каждого коммита — трейлер `Co-Authored-By` с текущей моделью Claude.
- Работа идёт в `main`, отдельные ветки — по решению автора.

Всё остальное (правка файлов, установка зависимостей, запуск и пересборка контейнеров,
миграции, скачивание моделей, запросы к API) делается без подтверждения.

## Запуск

Всё запускается через Docker Compose — на машине, кроме Docker, ничего не ставится.
Python-зависимости и воркспейс монорепо — через **uv** (один `uv.lock` на весь репозиторий).

Первый запуск: `cp deploy/.env.example .env` (необязательно) и `ollama pull qwen3.5:4b` на хосте.

```bash
docker compose up -d --build                       # поднять всё
docker compose logs -f api                         # логи сервиса
docker compose run --rm tools uv run pytest        # тесты
docker compose run --rm tools uv run ruff check .  # линтер
docker compose run --rm tools uv run ruff format . # форматирование
docker compose run --rm tools uv run mypy .        # типы
docker compose run --rm tools uv run pytest -m ollama  # живой тест на Ollama хоста
docker compose run --rm tools uv run pytest -m network # живая загрузка вакансии с hh.ru
docker compose run --rm api uv run alembic upgrade head
```

`tools` — служебный сервис для тестов и линтеров, чтобы не ставить окружение локально
(профиль `tools`: `up` его не поднимает). Репозиторий смонтирован в `/app`, venv лежит в `/opt/venv`.
После изменения зависимостей — `docker compose --profile tools build`. `api` накатывает миграции сам при старте.

## Процесс

- **Крупное** (новый модуль, новая фича, изменение API-контракта или схемы БД):
  сначала спека в `docs/specs/NNN-название.md` — цель, границы (что входит и что нет),
  API-контракт, критерии приёмки. Код — после того как автор одобрил спеку.
- **Мелкое** (баг, рефакторинг внутри модуля, правка текста) — сразу, без спеки.
- Если по ходу реализации спека оказалась неверной — сначала обновить спеку, потом код.

## Качество

- К каждой фиче — тесты на pytest.
- Перед каждым коммитом: тесты, `ruff check`, `ruff format --check`, `mypy`. Всё должно быть зелёным.
  Незелёное не коммитится.
- Внешние сервисы (LLM, Whisper, S3) в юнит-тестах мокаются через интерфейсы из `packages/*`,
  а не патчами внутренностей.

## Данные и секреты

- Никогда не коммитить `.env`, ключи API, аудиозаписи, веса моделей и данные экспериментов
  (`research/data/`). Для конфигурации — `.env.example` без реальных значений.
- Голосовые ответы — персональные данные: храниться только в хранилище развёрнутого инстанса,
  в логи и репозиторий не попадают.
- Документы диплома (Word, PDF и прочее из родительской папки) в репозиторий не попадают и не копируются.
