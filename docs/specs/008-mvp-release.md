# 008. Стабилизация и приёмка MVP

Статус: одобрена · 03.11.2026 · спринт 8 закрыт, тег `v0.1.0`; проход в Telegram — чеклист автора ([roadmap](../roadmap.md))

## 1. Цель

Незнакомый человек с Маком, Docker и Ollama клонирует репозиторий, за 3 команды поднимает Sobesnik по README
и проходит в боте путь С1 → С5 без помощи. Если что-то не так (Ollama не запущена, модель не скачана, нет
токена, VPN, занят порт), он видит понятный текст «что случилось и что сделать», а не трейсбек. Все 8 критериев
приёмки из [000 §11](000-overview.md#11-критерии-приёмки-mvp) проверены и записаны в таблицу, найденное
исправлено, после одобрения автора ставится тег `v0.1.0`.

Вход из прошлых спринтов (roadmap §8, 000 §5 и §11, 006 и 007 «Итоги»):

| Что | Чем закрывается | Раздел |
|---|---|---|
| профили `mac`, `gpu`, `cloud` | один compose, выбор строкой в `.env` | §4 |
| README «с нуля», 3 команды | новый README: установка, первый проход в боте, «если не работает» | §5 |
| `deploy/.env.example` с комментариями | переписать по группам, каждая переменная с «зачем» и «когда трогать» | §6 |
| сид тем | уже есть: `api` синхронизирует справочник при старте (`topics_sync`) — только проверить в чистой установке | §8 |
| понятные ошибки первого запуска | разбор 8 мест, где спотыкаются, тексты для бота, API и логов | §7 |
| прогон критериев 000 §11 | таблица «критерий → как проверил → результат» в «Итогах» | §9 |
| замеры по §5 на Mac | по одному прогону на шаг, в «Итоги» и в 000 §5 | §10 |
| замеры на GPU-сервере | сервера нет — помечается «не проверено» | §10 |

## 2. Границы

**Входит:**
- выбор профиля запуска в `.env`: `mac` (по умолчанию), `gpu`, `cloud`; GPU-оверлей compose с сервисом `ollama`
  и whisper на CUDA;
- порт API настраивается и по умолчанию открыт только на этом компьютере (решение 3);
- понятные сообщения о типовых сбоях в боте, в API (`/health/llm`) и в логах сервисов (§7);
- новый `README.md` и `deploy/.env.example`;
- проверка чистой установки в отдельной папке с отдельными томами (§8);
- прогон 8 критериев приёмки, фиксы найденного, замеры по 000 §5 на Mac;
- обновление 000 (§5 цифры, статус), roadmap, CLAUDE.md (команды профилей);
- тег `v0.1.0` — после «ок» автора; push тега — только по отдельной команде.

**Не входит:**
- реальный запуск профиля `gpu` — сервера нет: проверяем только, что конфигурация собирается (`docker compose config`)
  и образ строится; помечается «не проверено»;
- облачный ключ: `cloud` проверяется на OpenAI-совместимом endpoint самой Ollama (`/v1`), как требует критерий 5;
- новые функции из буфера (подробный разбор, генерация пачками, вопросы с неверной посылкой) — спринт 10;
- веб-кабинет — спринт 9;
- скачивание новых моделей: только `qwen3.5:4b` и whisper `small`, которые уже есть;
- долгие замеры и прогоны на нескольких моделях — критерий 6 закрыт в спринте 5, здесь короткий повтор (§9).

## 3. Отклонения от roadmap и 000

1. **«Профиль» — строка в `.env`, а не обязательный флаг `--profile`.** `mac` и `cloud` отличаются только
   переменными LLM, compose у них один и тот же. `gpu` добавляет оверлей `deploy/compose.gpu.yaml`
   через `COMPOSE_FILE` в `.env`. Так команда запуска одна для всех: `docker compose up -d`.
2. **Замер «1 минута речи» — через API**, на фрагменте записи из `research/data/asr_check` (~60 с), а не голосовым
   в Telegram: в Telegram длительность голосового не воспроизвести точно. Голосовое в 1 минуту в боте — отдельно,
   в проходе автора (критерий 3).
3. **Критерий 6 не перепрогоняется целиком.** Три модели на Mohler-30 и повтор при t = 0 сделаны в спринте 5
   (research/README.md). Здесь — короткий повтор той же конфигурации на `mohler-10` одной моделью, чтобы
   убедиться, что после спринтов 6–7 баллы всё ещё совпадают.

## 4. Профили запуска

| Профиль | Где LLM | Где whisper | Что в `.env` |
|---|---|---|---|
| `mac` (по умолчанию) | Ollama на хосте, `host.docker.internal:11434` | контейнер `worker`, CPU | ничего, кроме токена бота |
| `gpu` | контейнер `ollama` с GPU | контейнер `worker`, CUDA | `COMPOSE_FILE=compose.yaml:deploy/compose.gpu.yaml` |
| `cloud` | OpenAI-совместимый API | контейнер `worker`, CPU | `LLM_PROVIDER=openai_compatible`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |

В `deploy/.env.example` — три готовых закомментированных блока, раскомментировать нужный.

**`deploy/compose.gpu.yaml`** (оверлей поверх `compose.yaml`):
- сервис `ollama`: образ `ollama/ollama` с зафиксированной версией, GPU NVIDIA через
  `deploy.resources.reservations.devices`, том `ollama-models`, healthcheck;
- сервис `ollama-pull`: одноразовый, после healthy `ollama` выполняет `ollama pull ${LLM_MODEL}` — модель
  скачивается сама при первом `up`;
- `api` и `worker`: `LLM_BASE_URL=http://ollama:11434`; `worker` собирается из target `runtime-gpu`
  (CUDA-библиотеки для faster-whisper через pip-пакеты `nvidia-cublas-cu12`, `nvidia-cudnn-cu12`) и получает GPU,
  `ASR_DEVICE=cuda`, `ASR_COMPUTE_TYPE=float16`.

**Новая переменная `ASR_DEVICE`** (`cpu` | `cuda` | `auto`, по умолчанию `cpu`) — сейчас устройство whisper зашито.

**Порт API.** `ports: "127.0.0.1:${API_PORT:-8000}:8000"` (решение 3). Бот и `tools` ходят в API по внутренней
сети compose (`api:8000`), порт на хосте нужен только для `curl`, `/docs` и проверки в README.

## 5. README «с нуля»

Структура (русский, коротко, без истории спринтов):

1. **Что это** — 3 строки и скриншот-описание диалога словами (без картинок с персональными данными).
2. **Что нужно заранее:** Mac на Apple Silicon с 16 ГБ RAM (или Linux), Docker Desktop 4.27+ (compose 2.24+),
   Ollama, токен бота от @BotFather — как получить за минуту.
3. **Запуск — 3 команды** (+ скачивание модели, которое не считается):
   ```bash
   ollama pull qwen3.5:4b                                   # модель, ~3,4 ГБ, один раз
   git clone https://github.com/lama2x2/sobesnik && cd sobesnik
   cp deploy/.env.example .env                              # затем вписать токен в TELEGRAM_BOT_TOKEN=
   docker compose up -d --build
   ```
   и как понять, что всё поднялось: `docker compose ps` и строка «бот запущен: @имя_бота» в
   `docker compose logs bot`.
4. **Первая тренировка** — что написать боту по шагам: `/start` → вставить вакансию (текст или ссылка hh.ru) →
   «Начать тренировку» → ответ текстом → ответ голосовым → `/progress` → `/repeat`. Сколько чего ждать (цифры из §10).
5. **Если не работает** — таблица «что видите → что сделать» из §7.
6. **Другие профили:** GPU-сервер и облачная модель — по блоку в `.env`.
7. **Данные и приватность:** что где хранится, `/forget`, голос проходит через Telegram, закрыть бота от чужих
   (`BOT_ALLOWED_IDS`).
8. **Без бота: через API** — нынешние `curl`-примеры, сокращённо; `/docs`.
9. **Для исследователя** — ссылка на `research/README.md`. **Для разработки** — ссылка на CLAUDE.md-команды
   (тесты, линтеры).

Убрать устаревшее: «ранняя разработка, описанное — план», «веб-кабинет» как готовый интерфейс.

## 6. `deploy/.env.example`

- Сверху — «что заполнить обязательно» (одна строка: `TELEGRAM_BOT_TOKEN`) и «что желательно» (`BOT_ALLOWED_IDS`,
  `API_SERVICE_TOKEN`), затем блок выбора профиля (§4), затем остальное по группам.
- У каждой переменной: что делает, значение по умолчанию, когда менять. Технические (`DATABASE_URL`, `REDIS_URL`,
  `S3_*`, `ANSWER_EVENTS_STREAM`) — в конце, с пометкой «трогать не нужно».
- Добавить недостающие: `API_PORT`, `ASR_DEVICE`, `COMPOSE_FILE`, `COMPOSE_PROJECT_NAME` (закомментирована,
  «для второй копии на той же машине»), `ANSWER_EVENTS_STREAM`.
- Тест: каждая переменная из `Settings` API, воркера и бота есть в `.env.example` и наоборот — чтобы пример
  не расходился с кодом.

## 7. Где первый пользователь вероятнее всего споткнётся

Принцип: каждый типовой сбой даёт **одну понятную фразу «что случилось» + «что сделать»** там, где человек
смотрит в этот момент — в боте, в `curl /health/llm` или в `docker compose logs`. Трейсбек остаётся только для
неожиданных ошибок.

| # | Что случилось | Сейчас | Станет |
|---|---|---|---|
| 1 | **Модель не скачана** (`ollama pull` забыли) | бот: «Модель сейчас недоступна. Попробуйте через минуту» — ждать бесполезно | новый код `llm_model_missing` (503). Бот: «Модель qwen3.5:4b не скачана. На компьютере с Sobesnik выполните: `ollama pull qwen3.5:4b` — и пришлите вакансию ещё раз». То же в `/health/llm` (поле `hint`) и одной строкой в логе `api` при старте |
| 2 | **Ollama не запущена** | бот: «Модель сейчас недоступна» | код `llm_unavailable`, текст: «Не достучался до Ollama. Запустите приложение Ollama (или `ollama serve`) и попробуйте ещё раз». Для `cloud` — «облачная модель не отвечает, проверьте LLM_BASE_URL» |
| 3 | **Нет токена бота** | лог на английском, `bot` тихо в статусе Exited — человек не понимает, почему бот молчит | лог: «Бот не запущен: в .env пустой TELEGRAM_BOT_TOKEN. Получите токен у @BotFather (/newbot), впишите в .env и выполните `docker compose up -d`» |
| 4 | **Токен неверный** | трейсбек aiogram и бесконечный перезапуск (`restart: on-failure`) | лог: «Telegram не принял токен — скопируйте его заново у @BotFather», выход с кодом 0, без перезапусков |
| 5 | **Тот же токен у другой запущенной копии** | поток `TelegramConflictError` в логах | лог раз в минуту: «Этот токен уже использует другой запущенный бот — остановите вторую копию» |
| 6 | **Нет связи с Telegram** (VPN, сеть) при старте | трейсбек и перезапуск | лог: «Нет связи с api.telegram.org — проверьте интернет или VPN, повторю через 30 с», повтор без трейсбека |
| 7 | **VPN с fake-IP** — ни одна ссылка на вакансию не открывается | «Эту ссылку открыть нельзя» — непонятно, почему | `198.18.0.0/15` по умолчанию внешняя (решение 2) — ссылки работают сразу. Для других диапазонов (`240.0.0.0/4`) текст: «Похоже, включён VPN в режиме fake-IP… пришлите текст вакансии; чтобы ссылки работали — строка в .env (README)» |
| 8 | **Порт 8000 занят** | ошибка Docker `port is already allocated` — её не перехватить | в README: строка в таблице «если не работает» и `API_PORT=8001` в `.env`; бот от порта не зависит |

Ещё два места, где пользователь ждёт без объяснений:
- **Первое голосовое** — whisper `small` (~0,5 ГБ) скачивается при первом ответе, это до пары минут. Станет:
  воркер при старте в фоне докачивает модель, если её нет в томе, и пишет в лог «модель распознавания готова»
  или «не скачалась: …, голосовые не работают, текстом можно». Ответ голосом до конца загрузки ждёт её, статус
  в боте: «🎧 Готовлю распознавание (первый раз — пара минут)…» — не сделано, см. «Итоги».
- **Закрытый бот без своего id** — сейчас «Это закрытый инстанс Sobesnik». Станет: «Это закрытый Sobesnik.
  Ваш telegram_id: 123456 — владелец может добавить его в BOT_ALLOWED_IDS».

Плюс на `/start`: бот спрашивает `/health/llm`, и если модель недоступна — к приветствию добавляется
предупреждение из пунктов 1–2, ещё до того, как человек потратит время на вакансию. При старте `bot` пишет в
лог «бот запущен: @имя_бота, модель: qwen3.5:4b — ок | не скачана | Ollama недоступна».

**API-контракт:** новый код ошибки `llm_model_missing` (503) — в ответах API и в `failed`-событиях воркера;
`GET /health/llm` — поле `hint` у роли (строка или `null`). Остальное без изменений.

## 8. Проверка чистой установки

Свежий клон в отдельную папку, запуск строго по README, ничего из рабочей копии не трогаем:

1. `git clone` из GitHub (после push, если автор разрешит) или из локального репозитория — в
   `~/sobesnik-clean` (папка вне проекта; удаляется в конце).
2. В её `.env`: `COMPOSE_PROJECT_NAME=sobesnik-clean` и `API_PORT=8001` — свои контейнеры, тома (`sobesnik-clean_pgdata`
   и т. д.) и порт; рабочие данные в томах `sobesnik_*` не задеваются. Проверяется до `up`:
   `docker compose config` показывает новые имена томов.
3. Сборка с `--no-cache`, чтобы проверить Dockerfile с нуля.
4. Whisper `small` не скачивается заново: копируется из тома `sobesnik_asr-models` в `sobesnik-clean_asr-models`
   одноразовым контейнером.
5. Проверка: `/health`, `/health/llm`, темы засеяны (97 листовых), бот отвечает (решение 1: рабочий бот на это время остановлен).
6. Удаление: `docker compose -p sobesnik-clean down -v`, папка удаляется. Рабочий бот снова запущен.

## 10. Замеры времени (000 §5)

Mac M4 16 ГБ, `qwen3.5:4b`, whisper `small`, по одному прогону, модель прогрета (первый вызов после загрузки
в память записывается отдельно — его и почувствует новый пользователь).

| Операция | Ориентир Mac | Как меряю |
|---|---|---|
| разбор вакансии | ≤ 30 с | лог `api` в проходе автора |
| генерация 5 вопросов | ≤ 40 с | лог `api`; в проходе 3 вопроса → отдельно один `POST /sessions n=5` через API |
| оценка одного ответа | ≤ 30 с | лог `worker` |
| распознавание 1 минуты речи | ≤ 30 с | `research/asr_check/check.py --asr-only` на фрагменте ~60 с |
| подтверждение приёма в боте | ≤ 2 с | новое поле `ack_ms` в логе `bot`: от получения сообщения до статусного ответа |

Отклонения объясняются в «Итогах». Сервер с GPU — колонка «не проверено: нет доступа к серверу». После замеров
`ollama stop qwen3.5:4b`. Голоса и тексты ответов в логах и в «Итогах» не появляются — только время.

## 11. Тесты

Без Ollama, Telegram, сети и GPU.
- `packages/llm`: Ollama 404 на модель → `LLMModelMissingError` (подкласс `LLMUnavailableError`, старые
  обработчики не ломаются); `health()` возвращает `hint`.
- API: `llm_model_missing` → 503 с этим кодом; `/health/llm` с `hint`; адрес из `198.18.0.0/15` разрешён по умолчанию, из `240.0.0.0/4` — понятный текст про VPN.
- Воркер: модель не скачана → `failed` с кодом `llm_model_missing` после последней попытки; предзагрузка whisper —
  через интерфейс `Transcriber` (фейк), сбой загрузки не валит воркер.
- Бот: тексты для `llm_model_missing` и `llm_unavailable`; `/start` с недоступной моделью добавляет предупреждение;
  неверный токен → понятный лог и код выхода 0; конфликт токена и нет сети → понятный лог без трейсбека;
  отказ allowlist показывает id; `ack_ms` в логе.
- `.env.example` ↔ `Settings`: все переменные на месте (§6).
- compose: `docker compose config` для `mac` и `gpu` — проверка руками, в «Итогах».

## 12. Порядок работы

1. Понятные ошибки (§7) + тесты → коммит.
2. Профили, `API_PORT`, `ASR_DEVICE`, `compose.gpu.yaml`, `runtime-gpu` → коммит.
3. `.env.example` и README → коммит.
4. Тесты, линтеры, mypy (критерий 8).
5. Чистая установка (§8) и проход автора в Telegram (критерии 1–3, 7), замеры (§10).
6. Критерии 5 и 6 через API и CLI, `ollama stop`.
7. Фиксы найденного → коммиты; «Итоги», 000 §5, roadmap ✅, CLAUDE.md.
8. «Ок» автора → `git tag -a v0.1.0`. Push коммитов и тега — только по команде автора.

**Что выяснилось:**
- Конфликт токена проверен вживую (обе копии запущены): понятная строка раз в минуту. aiogram при этом пишет
  «Sleep for … try again» каждые несколько секунд — после понятной строки эти повторы теперь скрыты.
- «Нет связи с api.telegram.org» проверено вживую: рабочий бот после перезапуска минуту не мог достучаться до
  Telegram и подключился сам, без трейсбека.
- Модель не скачана / Ollama не запущена — подсказки проверены на живой Ollama (несуществующая модель, неверный порт).
- whisper при старте воркера «докачивается» за 0,9 с, если модель уже в томе (запрос к Hugging Face за ревизией).
- Подсказка «Готовлю распознавание (первый раз — пара минут)» в боте не сделана: воркер качает модель сам при
  старте, бот не знает, готова ли она; первое голосовое просто ждёт загрузку.

**Профиль gpu:** `docker compose config` с оверлеем проходит, CUDA-пакеты резолвятся под linux/amd64; образ
`runtime-gpu` (~3 ГБ) не собирался (на Маке не запустится, мало места на SSD), на GPU не запускался — **не проверено**.
