# research/: качество оценки

Эксперименты Sobesnik. Код и выводы лежат здесь, а данные, выгрузки и графики — только в `research/data/`
(в git не попадает). Спека — [005-quality](../docs/specs/005-quality.md).

| Папка | Что |
|---|---|
| `generation_bench/` | замер разбора вакансий и генерации вопросов (спринты 2–3) |
| `eval_check/` | быстрая живая проверка оценки через API (спринт 3) |
| `asr_check/` | нарезка фрагментов записей, замер whisper, поиск вопросов в записях (спринты 4–5) |
| `datasets/` | конвертеры открытых датасетов в единый JSONL (спринт 5) |
| `quality/` | эталонные расшифровки `large-v3` и отчёт «модель × метрика» (спринт 5) |
| `repetition/` | симуляция: правило «слабая тема» против SM-2 под шумом оценщика (спринт 11) |

## Данные

| Датасет | Что | Лицензия | В БД |
|---|---|---|---|
| [Mohler ASAG 2011](https://huggingface.co/datasets/nkazi/MohlerASAG) | 2 273 ответа студентов курса «структуры данных», эталон преподавателя, оценки двух людей 0–5 | CC BY 4.0 | `mohler-30`, `mohler-10` (стратифицированные выборки) |
| [yakimka/python_interview_questions](https://github.com/yakimka/python_interview_questions) @ `d4e0aed` | банк вопросов к Python-собеседованию на русском | MIT | `ru-ladder`: 8 вопросов × 4 ответа известного качества |
| записи собеседований автора | 10 ответов по 26–90 с, вопросы найдены whisper по полным записям | личные, только локально | `voice-10` |

Цитирование Mohler: Mohler M., Bunescu R., Mihalcea R. *Learning to Grade Short Answer Questions using Semantic
Similarity Measures and Dependency Graph Alignments.* ACL-HLT 2011.

## Как воспроизвести

Всё в `tools`: `docker compose run --rm tools uv run …`. После прогонов: `ollama stop <модель>`.

```bash
# 1. данные → JSONL → БД
python research/datasets/mohler.py
python research/datasets/ru_bank.py
sobesnik-cli dataset import research/data/datasets/mohler.jsonl --sample 30
sobesnik-cli dataset import research/data/datasets/ru_ladder.jsonl

# голос: ffmpeg полной записи → find_questions.py → cut.sh по фрагменту → fragments.yaml
python research/datasets/voice_fragments.py
sobesnik-cli dataset import research/data/asr_check/voice.jsonl      # воркер распознаёт small
python research/quality/reference_asr.py --dataset voice-10          # эталон large-v3

# 2. прогоны (по одному на модель)
sobesnik-cli eval-run create --name mohler-gemma3-4b --dataset mohler-30 --model gemma3:4b --wait
sobesnik-cli eval-run create --name stab-t07-s1 --dataset mohler-10 --temperature 0.7 --seed 1 --wait
sobesnik-cli eval-run create --name voice-ref-v3 --dataset voice-10 --transcript reference --wait

# 3. CSV → отчёт
sobesnik-cli export --dataset mohler-30 --run RUN_ID … -o research/data/quality/mohler-models.csv
python research/quality/report.py research/data/quality/*.csv -o research/data/quality/report.md
```

`report.py` читает только CSV: из одних и тех же файлов всегда получается один и тот же отчёт
и `delta_wer.png`.

|---|---|---|---|---|---|
| `qwen3.5:4b` | **0,84** [0,64; 0,93] | 0,58 [0,37; 0,75] | **22,1** | 15,6 | 0 % |
| `gemma3:4b` | 0,72 [0,44; 0,88] | **0,67** [0,44; 0,81] | 23,4 | 11,1 | 0 % |
| `llama3.2:3b` | 0,45 [0,07; 0,73] | 0,32 [0,04; 0,56] | 28,2 | 7,7 | 0 % |
| `qwen3:1.7b` | 0,44 [−0,02; 0,74] | 0,40 [0,09; 0,62] | 29,1 | 5,9 | 0 % |
| ориентир: человек × человек (26 ответов) | 0,68 | 0,62 | 22,7 | — | — |
| `qwen3.5:4b`, промпт v2 (без эталона) | 0,69 [0,44; 0,85] | 0,43 [0,20; 0,65] | 26,3 | 20,9 | 0 % |

**Русская «лестница», 8 вопросов × 4 ответа** (эталон 3 > половина 2 > чужой ответ и «не знаю» 0):

| Модель | порядок верный | ρ с уровнем | медиана, с |
|---|---|---|---|
| `qwen3.5:4b` | **8 из 8** | 0,94 | 18,3 |
| `gemma3:4b` | 6 из 8 | 0,93 | 11,8 |
| `llama3.2:3b` | 4 из 8 | 0,74 | 8,4 |
| `qwen3:1.7b` | 3 из 8 | 0,77 | 7,1 |

**Согласие моделей между собой** (Mohler, ρ): `qwen3.5:4b` × `gemma3:4b` — 0,84; пары с маленькими моделями —
0,17–0,48. На «лестнице» все пары ≥ 0,76: грубый порядок видят все, тонкий — только 4B.

**Стабильность** (`qwen3.5:4b`, 10 ответов Mohler): повтор при t = 0 — итог совпал у 10 из 10. При t = 0,7
с тремя seed итог гуляет в среднем на ±10,4 балла.

**Влияние распознавания** (`qwen3.5:4b`, v3, 10 фрагментов): WER `small` против `large-v3` — 5–28 %, в среднем 13 %.
Средняя |Δ| итога между оценками по `asr` и по `reference` — 18 баллов, но с WER она не связана
(ρ = 0,02). Δ = +80 у фрагмента про идемпотентность: по эталонной расшифровке модель поставила 20 и придумала
ошибку («неправильный термин „идемпотентность“ вместо „идемпотентность“»). Разброс даёт сам оценщик: на устных
ответах без эталона и ключевых пунктов маленькая модель чувствительна к любой перестановке слов.
`large-v3` на CPU в Docker: 27–78 с на минуту речи против 6–10 с у `small`.

**Сомнения в распознавании:** 28 пунктов на 10 ответов и у v2, и у v3. Простого написания кириллицей почти
не осталось. Полезные пункты — примерно треть («рак» → RAG, «Селлари» → Celery, «update4» → FOR UPDATE,
«инио» → `__new__`). Остальное — стилистические перефразы, к распознаванию не относящиеся («закрыт доступ» →
«скрыт от глаз»). Модель ещё и писала с опечаткой «распизнано»; теперь это чинит `repair`.

**`wrong_points`:** 0 непустых из 11 оценок вопросов с ключевыми пунктами за спринты 3–5.

## Выводы

1. **Модель по умолчанию остаётся `qwen3.5:4b`.** Лучший Спирмен на Mohler, и он выше согласия людей между собой
   (0,84 против 0,68). Единственная прошла «лестницу» 8 из 8, медиана 16–18 с при ориентире ≤ 30 с.
   Запасной вариант — `gemma3:4b`: на треть быстрее, лучший QWK, но ошибается в порядке на 2 вопросах из 8.
   Модели меньше 4B для оценки не годятся: ρ ≈ 0,45, хотя формат держат все.
2. **Промпт v3 остаётся боевым.** Эталонный ответ в промпте поднял ρ с 0,69 до 0,84 на тех же ответах, а «не знаю»
   больше не получает «фактически верное» обоснование. Шум в сомнениях распознавания v3 не убрал — это
   задача на спринт 10: фильтровать в коде пункты, где «сказано» совпадает с «распознано» после транслитерации,
   или поднять порог.
3. **Абсолютный балл модели надо читать с допуском ±20.** MAE 22 — на уровне расхождения двух людей (22,7),
   при t > 0 итог гуляет на ±10, а на устных ответах без эталона — на ±18 между почти одинаковыми текстами.
   Порядок (лучше или хуже) надёжнее абсолютного числа. Для прогресса по темам (спринт 7) это довод
   усреднять несколько последних оценок, а не смотреть на одну.
4. **Ошибки распознавания `small` (WER ≈ 13 %) — не главный источник ошибок оценки.** Связи Δ с WER нет:
   разброс самого оценщика больше. Модель распознавания по умолчанию остаётся `small`.
5. **Рубрика не меняется.** Метрики не показали критерия, который ломает оценку. Главные проблемы — нехватка
   эталона и шум маленькой модели, а не формулировки уровней.
6. **`wrong_points` пользы не показал** (0 из 11). Поле дешёвое, пользователю не видно — оставляем,
   вопрос закрыт.

## Ограничения

- Выборки маленькие (30 ответов Mohler, 32 — «лестница», 10 — голос) по просьбе автора: Мак 16 ГБ греется.
  Доверительные интервалы широкие, разница меньше ~0,2 по ρ не значима.
- Mohler — английский и про структуры данных, а промпт и обоснования русские. Русских датасетов
  с оценками людей не нашлось. «Лестница» синтетическая и проверяет только порядок.
- Эталон расшифровки — `large-v3`, а не человек (решение автора). WER — это расхождение двух распознавателей.
  Термины латиницей против кириллицы считаются ошибками WER, хотя смысл не меняют.
- Голосовые фрагменты отвечают на вопросы настоящих собеседований: эталона и ключевых пунктов у них нет,
  полноту модель оценивает по своему пониманию.

## Повторение: правило «слабая тема» против SM-2 (спринт 11, 011 §5.5)

`python research/repetition/simulate.py` — симуляция без LLM и БД, ~5 с. Выбор тем — кодом продукта
(`sobesnik_core.progress`, `repetition`); допущения модели ученика — в шапке скрипта: знание забывается по
экспоненте, у тем разная скорость забывания, каждая попытка учит и замедляет забывание, в день — одно
повторение до 5 тем. 10 тем, 60 дней, 200 прогонов на строку:

| σ шума | Правило | Знание в конце | Забыто тем | Повторений | Из них впустую |
|---|---|---|---|---|---|
| 0 | слабая тема | 37,6 | 9,4 из 10 | 24,3 | 0,0 |
| 0 | раз в неделю | 89,0 | 0 | 80,0 | 16,2 |
| 0 | SM-2 | 85,7 | 0 | 73,7 | 16,0 |
| 0 | SM-2 по двум | 89,8 | 0 | 81,9 | 31,6 |
| 10 | слабая тема | 37,6 | 9,0 из 10 | 24,0 | 0,7 |
| 10 | SM-2 | 88,7 | 0 | 80,8 | 30,0 |
| 20 | слабая тема | 37,0 | 8,5 из 10 | 22,4 | 2,1 |
| 20 | раз в неделю | 89,0 | 0 | 80,0 | 16,2 |
| 20 | SM-2 | 92,0 | 0,1 из 10 | 94,0 | 46,3 |
| 20 | SM-2 по двум | 90,9 | 0,1 из 10 | 89,0 | 41,9 |

«Забыто» — знание к концу ниже 60; «впустую» — повторение темы, которую человек и так знал (≥ 80).
«SM-2 по двум» — в алгоритм идёт среднее попытки и предыдущей.

**Выводы:**
- Главный выигрыш — что тема **вообще возвращается**: правило «слабая тема» никогда не повторяет сданную тему,
  и к 60-му дню забыто 9 из 10 тем. Любое повторение по сроку держит знание около 90.
- SM-2 **не лучше** фиксированного «раз в неделю» в этой модели: на её коротком горизонте и при
  экспоненциальном забывании недельный интервал оказывается почти оптимальным. Преимущество SM-2 —
  в адаптации к теме — модель показывает слабо.
- **Шум оценщика стоит SM-2 повторений:** при σ = 20 (допуск балла, analysis §2.3) повторений на 28 % больше,
  чем без шума, и половина из них — по уже известным темам: случайно низкий балл сбрасывает интервал.
  Сглаживание по двум попыткам снимает часть этой цены (94 → 89), но без шума делает хуже.
- Это аргумент из модели, а не замер на людях: параметры ученика выбраны, а не измерены.
